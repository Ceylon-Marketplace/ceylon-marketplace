# CM-### — Short task title

- **Status:** In progress | Blocked | Completed
- **Owner:** Manoj | Naveen
- **Agent:** None | Name (Model)
- **Started:** YYYY-MM-DD
- **Completed:** YYYY-MM-DD | Not completed
- **Areas:** comma-separated domains or components
- **Likely files:** paths or globs expected to change
- **Branch:** branch name
- **PR:** URL or `Not opened`

## Outcome

Describe the intended user-visible or operational result, not the implementation steps.

## Acceptance criteria

- [ ] A concrete, verifiable result
- [ ] Relevant documentation is current
- [ ] Required verification passes

## Dependencies

List prerequisite tasks, decisions, external input, or `None`.

## Coordination notes

Record overlapping active tasks, shared contracts or migrations, and the agreed integration order. Write `None identified` when there is no overlap.

## Implementation summary

Complete this before moving the task to `completed/`. Summarize the delivered result and link to relevant decisions or domain docs; do not duplicate the Git diff.

## Verification

Record build, typecheck, lint, automated tests, and relevant manual QA. Explain any skipped check.

## Remaining work

Keep this current while work is active or blocked. Write `None` before completion; follow-up scope should receive a new task ID.
